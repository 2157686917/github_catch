# 活人感写作（human-writing）：让 AI 写出有"人味"的中文

## 痛点：为什么 AI 写的中文总有一股"机器味"

用过 AI 写中文内容的人，多半遇到过同样的尴尬：文章读起来流畅、完整，但就是"不对劲"——段落之间原地打转，每段都在重复上一段的结论；用词堆砌"赋能""抓手""闭环"这类黑话；动不动就冒号、破折号连用；最要命的是，它写"真人真事"时张口就来，事实、数字、引语出处都经不起追问。

这些问题的根源，不是模型不够聪明，而是缺少一套**针对中文的写作纪律**：没人告诉 AI 什么是"事实"，什么是"虚构"；没人强制它"每个新段落必须带来新信息"；也没人帮它清除藏在成稿里的"模型腔"。

## 效果演示：一句话让 Agent 改头换面

human-writing 是一个开源的 Agent Skill（技能包），安装后只需一句话即可调用：

```text
使用 $human-writing，把我的材料写成一篇有活人感和中文韵律的作品。
```

它不同于普通的"文风提示词"——不是靠哄着模型"写得自然一点"，而是把一套完整的写作流程注入 Agent：先确认材料够不够，再处理结构、节奏和措辞，最后按硬规则逐条检查成稿。

## 核心功能：三件事，管住中文写作的命门

项目把写作拆成三件可执行的事：

| 01 材料 | 02 推进 | 03 中文 |
| :--- | :--- | :--- |
| 现实写作核准事实、数字、引语和亲历；虚构写作检查人物、行动与因果 | 每个新段落都要带来新事实、新动作、新例子、新区别或新后果 | 白话打底，重视词序、停顿、照应和分寸，清除报告腔与模型腔 |

这套设计的精妙之处在于**入口处现实/虚构分流**：写真人真事时，材料不够就先研究、追问或缩短，绝不用想象补事实；写小说故事时，允许创造人物、场景、对白和情节，但仍要求每个主要场景有目标、动作或变化。两种写法各用各的标准审稿，互不干扰。

初稿完成后，Skill 会做一轮硬规则检查：删掉重复解释，处理中文节奏，清除冒号、破折号、翻案句、商业黑话和常见模型腔；仓库自带的 `check_prose.py` 脚本会逐条核查成稿是否命中明确禁用项，只执行写明的规则，不替作者决定文体。

## 部署步骤：两分钟装进你的 Agent

human-writing 目前版本 **1.0.0**，MIT 协议开源，涵盖知乎回答、论坛长帖、公众号文章、博客、评论、人物故事、历史叙事、行业解读、科普、教程、评测、个人叙事、小说、故事、对白、口播、演讲稿等十余种文体。

**方式一（推荐）**：直接把下面这句话发给你的 Agent：

```bash
帮我安装这个skill：https://github.com/KKKKhazix/human-writing
```

Agent 会读取仓库、找到 `human-writing` 并完成安装，安装后显示名为「活人感写作」。

**方式二（手动）**：从 [Releases](https://github.com/KKKKhazix/human-writing/releases/latest) 下载 `human-writing.skill`，或把仓库里的 `human-writing` 文件夹完整复制到本机 Skills 目录（文件夹名必须保留为 `human-writing`）：

```text
~/.agents/skills/human-writing/
```

## 总结评估

human-writing 解决的是一个非常具体且普遍的痛点：**AI 中文写作的"人味"问题**。它没有追求炫技，而是把编辑的功夫落成一套可执行、可检查的流程规则，尤其适合知乎/公众号/小说等中文内容创作者给自己的 Agent 建立稳定的写作底线。

需要留意的是，它本质上是"规则 + 检查脚本"，实际效果仍取决于底层模型对中文的理解力；且现实写作部分强调"材料来路可考"，这需要你在调用时提供足够的原始材料。当前仓库 star 数约 615（2026-08-05，GitHub API），仍在快速迭代中，遇到规则误报或模型表现异常，可以在仓库 Issues 中带上原始提示词、输出片段和预期结果反馈。

**一句话总结**：如果你的 AI 写中文总差一口气，试试给它装一个"主编"——活人感写作，正是那个帮你把"模型腔"改成人话的开源 Skill。
